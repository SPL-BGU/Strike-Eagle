# Strike-Eagle PDDL Agent — ENHSP Pipeline Context

This document explains how the Strike-Eagle agent solves Angry Birds / Science
Birds levels by encoding each level as a **numeric temporal PDDL problem** and
solving it with the **ENHSP** planner (Expressive Numeric Heuristic Search
Planner). It is intended as a reference for anyone extending the agent.

---

## 1. High-Level Flow

```
Vision (GroundTruthReader)
        │
        ▼
Object extraction  ──►  problem_data dict
(pddl_objects.py)
        │
        ▼
write_problem_file()  ─────►  agents/pddl/pddl_files/problem.pddl
inject_domain_file()  ─────►  agents/pddl/pddl_files/base_domain_modified.pddl
        │
        ▼
ENHSP  (java -jar enhsp-20.jar -planner sat-hmrp)
        │
        ▼
solution.pddl  ──►  parse_solution_to_actions()  ──►  (force, angle)
        │
        ▼
AngleCalibrator.game_pull_for_pddl_dial()  →  slingshot pull
TrajectoryPlanner.find_release_point_partial_power()
BaselineAgent.shoot_and_record_ground_truth()
        │
        ▼
Ground-truth trajectory  ──►  segments (events)  ──►  learn physics
                                                    │
                              updates knowledge base (kb) / world_model
                                                    │
                                                    └──► next inject_domain_file()
```

The main entry point is `PDDLAgent.solve()` in
`agents/pddl/pddl_agent.py`, which calls `get_action_to_perform()` to plan and
then executes the shot.

## 2. PDDL Domain

**Files**

- `agents/pddl/pddl_files/base_domain.pddl` — template with injection sentinels
  (`{SE-collision-ground-effect}`, `{SE-collision-platform-effect}`).
- `agents/pddl/pddl_files/base_domain_modified.pddl` — the file ENHSP actually
  reads. Rewritten every plan by `inject_domain_file()` with learned collision
  effects substituted in.

**Domain:** `angry_birds_scaled`

**Requirements:** `:typing :disjunctive-preconditions :fluents :time
:negative-preconditions :conditional-effects`

**Types:** `bird`, `pig`, `block`, `platform`, `external_agent`

### Predicates (selected)

| Predicate | Meaning |
|-----------|---------|
| `bird_released ?b` | Bird has been launched |
| `pig_dead ?p` | Pig eliminated (goal) |
| `angle_adjusted` | Angle dial locked after shot setup |
| `force_locked` | Force value chosen for this shot |
| `pig_killed` | Any pig has died (global flag) |
| `block_explosive ?bl` | TNT-like block |
| `bird_tapped ?b` | Special power used |

### Numeric fluents

- **Slingshot dial:** `angle`, `angle_rad`, `angle_rate`, `min_angle`,
  `max_angle`, `cosine`, `sinus`.
- **Force search:** `v_bird_multiplier` ∈ [0.2, 1.0], `force_rate`, `min_force`,
  `max_force`.
- **Physics:** `gravity`, `active_bird`, `bounce_count`.
- **Per bird:** `x_bird`, `y_bird`, `vx_bird`, `vy_bird`, `v_bird`, `m_bird`,
  `bird_radius`, `bird_type`.
- **Per pig / block / platform:** position, size, life, mass.

### Processes (continuous)

| Process | Effect |
|---------|--------|
| `increasing_angle` | Sweeps `angle` down at `angle_rate`; updates `angle_rad`, `cosine`, `sinus` via Taylor approximation |
| `decreasing_force` | Steps `v_bird_multiplier` down at `force_rate` (0.2–1.0 grid) |
| `flying` | Ballistic integration of `x_bird`, `y_bird`, `vy_bird` with `gravity` |
| `agent_movement` | External-agent motion (novelty scenarios) |

### Actions

| Action | Effect |
|--------|--------|
| `set_force ?b` | Locks `force_locked` |
| `pa-twang ?b` | Launch: sets `vx/vy = v_bird * v_bird_multiplier * (cos/sin)`, applies position kick `(-16·cos, -12·sin)`, sets `bird_released` |
| `yellow_bird_action`, `white_bird_action`, `black_bird_action` | Special-bird powers |
| `switch_bird` | Multi-bird handoff |

### Events (exogenous)

- `collision_ground` — ground bounce; **learned M5 model injected** at the
  `{SE-collision-ground-effect}` sentinel.
- `collision_pig_kill`, `collision_block`, `collision_block_bounce_off` —
  block/pig damage & ricochet.
- `remove_unsupported_block`, `explode_block` — structural collapse.
- `collision_platform` — platform contact; learned slide/M5 model or a
  pessimistic hard-stop injected at `{SE-collision-platform-effect}`.
- `explode_bird` — end flight (3 bounces or `x ≥ 800`).
- `explode_pig`, `remove_unsupported_pig` — indirect pig kills.

## 3. Problem Encoding

**File:** `agents/pddl/pddl_files/problem.pddl` (regenerated per plan)

Generated by `generate_pddl()` / `write_problem_file()` in
`agents/pddl/pddl_files/pddl_parser.py` from a `problem_data` dict built in
`PDDLAgent._gather_problem_data()`.

Conventions:

- **Coordinate system:** `pddl_y = 640 - screen_y`; ground `PLAYFIELD_FLOOR_Y = 360.0`.
- **Bird init position:** the slingshot **reference point**, not the visual
  bird center. `pa-twang` moves the bird to the launch point via its kick.
- **Angle init:** `= (angle) max_angle`; `increasing_angle` sweeps it down.
- **Force init:** `= (v_bird_multiplier) 1.0`; `decreasing_force` steps down.
- **Goal:** `(and (pig_dead pig_0) (pig_dead pig_1) ...)`.
- **Learned physics:** `gravity` and per-bird `v_bird` come from the KB.
- Keys prefixed `_` in `problem_data` (e.g. `_block_angle`) are for
  visualization / debug only and are **not written to PDDL**.

### Object extraction (`pddl_objects.py`)

| Function | Produces |
|----------|----------|
| `get_birds(vision, sling, tp, world_model, ref_angle_guess)` | Bird fluents at sling ref point |
| `get_pigs(vision, sling, tp)` | Pig position/radius/life (center of MBR) |
| `get_blocks(vision, sling, tp)` | Conservative AABBs via `block_bbox_from_game_object()`; **ice ignored** |
| `get_platforms(vision, sling, tp)` | Hill/platform MBRs |

## 4. ENHSP Invocation

**Binary:** `agents/pddl/pddl_files/enhsp-20.jar` (runtime dependency, not in
git). Only `planners/ENHSP.class` is committed.

Working directory is changed to `agents/pddl/pddl_files/` before invocation so
that `problem.pddl`, `base_domain_modified.pddl`, and `solution.pddl` are all
resolved relative to that folder.

```python
enhsp_cmd = [
    'java', '-Xmx4g', '-jar', 'enhsp-20.jar',
    '-o', 'base_domain_modified.pddl',
    '-f', 'problem.pddl',
    '-sp', 'solution.pddl',
    '-planner', 'sat-hmrp',   # satisficing, metric relaxed-plan heuristic
]
subprocess.run(enhsp_cmd, timeout=200, env={..., '_JAVA_OPTIONS': ''})
```

Debug output is captured in `agents/pddl/pddl_files/enhsp_out.txt`.

### Two-pass strategy — `_run_enhsp_planner()`

| Pass | When | Platform model | Blocks |
|------|------|----------------|--------|
| **A** | Always first | Pessimistic hard-stop if platforms present | Raw geometry |
| **B** | Pass A returned `unsolvable` **and** layout is block-sheltered | Slide / M5 platform model | `apply_block_shelter_adjustments()` — tighter AABBs, weaker `block_life` |

Each pass:

1. `write_problem_file('agents/pddl/pddl_files/problem.pddl', ...)`
2. `inject_domain_file('agents/pddl/pddl_files/base_domain.pddl', world_model,
   defer_ground_m5=False,
   planning_pessimistic_platform=<pass A>)`
   Platform collision inject order: M5 (n≥21) → LR (v_x R²≥0.5) → slide placeholder.
3. Delete stale `solution.pddl`.
4. Run ENHSP.

### Failure handling

- `"unsolvable"` in stdout/stderr → return `(None, output)`. Snapshots of the
  problem/domain are saved under
  `agents/pddl/pddl_files/_unsolvable_snapshots/`.
- Missing `solution.pddl` file → treated as failure.
- After parsing: dial-executability check via `AngleCalibrator`, plus optional
  forward-sim rejection.

If planning fails, the agent falls back (mode-dependent) to `sim_search`, a
ballistic estimate (`_calculate_fallback_ballistic_angle`), or a coarse grid
search (`_search_fallback_by_sim`).

## 5. Parsing the Plan

**Function:** `parse_solution_to_actions()` in `pddl_parser.py`.

ENHSP writes a temporal plan such as:

```
0.0: (set_force bird_0)
3.0: (pa-twang bird_0)
```

Mapping used by the agent:

- **`set_force` at time `t`** → `force = FORCE_MAX - t * FORCE_RATE`
  (starts at 1.0, steps of 0.1 down to 0.2).
- **`pa-twang` at time `t`** → `angle = init_angle - t * angle_rate`
  where `init_angle = max_angle` from the problem.

Returned as a list, e.g. `[('set_force', 0.85), ('shoot', 68.0)]`. Extracted
in `PDDLAgent._extract_force_angle()`.

## 6. Executing the Shot

1. Snap the dial angle to the ENHSP grid (`align_dial_to_planner_grid`, default
   `deg_step=0.5°`).
2. `AngleCalibrator.game_pull_for_pddl_dial(angle, force)` → slingshot pull in
   degrees (nonlinear, force-dependent mapping learned online).
3. `pddl_force_to_v_portion(force)` → partial-power release value.
4. `TrajectoryPlanner.find_release_point_partial_power(sling, radians(pull),
   v_portion=...)` → mouse release point.
5. `BaselineAgent.shoot_and_record_ground_truth(x, y, ...)` executes the shot
   and records the GT trajectory.

**Force constants** (`pddl_parser.py`):

```python
FORCE_MIN = 0.2
FORCE_MAX = 1.0
FORCE_RATE = 0.1
MAG_MULT   = 0.5   # keeps shots in linear force→velocity regime
```

## 7. Feedback Loop — Learning Physics

After each shot:

1. `extract_real_trajectory()` (in `trajectory_parser.py`) converts GT batches
   into `{object: [(x, y), ...]}`.
2. `getSegmentsEvents()` (`segments.py`) splits the bird trajectory at physical
   events (ground / platform / block / hit). Event detectors live in
   `agents/pddl/pddl_files/events/event_conditions.py`.
3. **Segment 0** (before the first event) = free flight → fed to
   `learn_flight_physics()` → `learn_process_transitions()`, which uses
   polynomial fitting and grid search from `optimizer.py` to update
   `gravity`, `velocity`, and transition polynomials in the world model.
4. **Collision segments** → `learn_collision_effects()` and
   `learn_platform_effects()` fit **M5 piecewise-linear models** that are
   written back into the domain by the next `inject_domain_file()` call.
5. `AngleCalibrator.record_shot()` updates the dial ↔ measured-flight mapping.

Learning runs only during the **train** phase (`should_learn=True`); the
**test** phase reuses the accumulated KB but does not update it.

## 8. Retry / Fallback Machinery (train)

| Function | Role |
|----------|------|
| `_diversify_plan_for_retry()` | Perturb ENHSP dial ±6° / ±12°, tweak force on retries |
| `_try_sim_search_plan()` | Angle × force grid scored by the Python forward sim |
| `_calculate_fallback_ballistic_angle()` | Two-arc ballistic estimate |
| `_search_fallback_by_sim()` | Coarse sim grid when ENHSP fails outright |
| `_sim_plan_is_acceptable()` | Requires pig kill + no bad platform/block stop |
| `_plan_is_platform_hit_short()` | Narrow train-only sim gate |
| `_plan_is_block_shelter_miss()` | Block absorbs shot short of pig |

`max_train_attempts` (default 5) caps retries per training level.

## 9. Phy-Q Evaluation

- `agents/pddl/phyq_generalization.py` — `PhyQGeneralizationProtocol`
  implements the paper's evaluation splits:
  - **Local:** 80/20 within each template.
  - **Broad:** train templates vs held-out test templates.
  Level lists come from `config_phyq_*.xml` via `parse_sciencebirds_config()`.
- `agents/pddl/phyq_metrics.py` — `PhyQMetrics.compute_phyq_score()` is the
  mean pass rate across the 15 Phy-Q scenarios × 100. `PhyQLevelMapper` maps
  1-indexed game levels to XML config paths.

## 11. Notable Design Decisions

1. **Numeric temporal planning.** Angle and force are continuous processes
   swept in time; the planner chooses *when* to lock force and fire.
2. **Learned physics in PDDL.** Ground/platform bounce effects are piecewise
   M5 models injected as PDDL numeric effects, so the planner and the Python
   forward simulator share exactly the same knowledge base.
3. **Execution gap.** PDDL dial ≠ raw game pull; `AngleCalibrator` closes the
   loop from observed shots to keep dial commands executable.
4. **Planner vs sim divergence.** The Python forward sim
   (`simulate_pddl_shot_plan`) can reject or replace an ENHSP plan; a
   pessimistic platform pass avoids false-negative "unsolvable" on hill-graze
   layouts.
5. **Two-pass planning.** Pass A uses a pessimistic platform stop; Pass B
   relaxes platform and block models only when Pass A is unsolvable and the
   layout is block-sheltered.
6. **Train-only learning.** Test phase skips model updates but still plans
   with all accumulated KB.
7. **Force semantics.** PDDL `force = 1.0` ≠ full screen pullback; `MAG_MULT =
   0.5` keeps shots in the linear force→velocity regime for reliable learning.
